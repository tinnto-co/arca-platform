## Architecture

**Domain**: Argentine accounting/payroll platform. Manages AFIP invoices, IVA scraping, AFIP notifications, and a full payroll liquidation module (sueldos) with CCT/convenio support.

**Stack**: React 19 + TanStack React Start (SSR) + TanStack Router (file-based) + React Query + Drizzle ORM + PostgreSQL + Better Auth + Tailwind CSS 4 + Bun runtime.

**Data flow**: Route components → `useQuery`/`useMutation` → Server Functions (`src/actions/`) → Drizzle ORM → PostgreSQL. Server functions also dispatch async jobs to an external ARCA Scrapper service.

**Production server**: `server.ts` handles static asset preloading, gzip compression, and ETag caching. Also schedules the monthly payroll-cron (runs day 20 of each month via `src/lib/payroll-cron.ts` to auto-update salary scales).

### Key directories

- `src/routes/` — File-based routes. `__root.tsx` is the app shell (QueryClientProvider, Toaster). `_authed/route.tsx` is the auth-guarded layout — all children require a session with an active org. Public routes: `/login`, `/api/auth/*`, `/invite.$invitationId`.
- `src/actions/` — All backend logic as `createServerFn()` handlers. Always call `getSessionWithOrg()` first (from `src/actions/helpers.ts`).
- `src/components/ui/` — Radix UI primitives (shadcn-style). Use these for all UI primitives.
- `src/components/sueldos/` — Payroll-specific UI components.
- `drizzle/schema.ts` — Main DB schema (868 lines). `drizzle/auth.ts` — Better Auth tables.
- `lib/auth.tsx` — Better Auth server config with organization + admin plugins. `lib/auth-client.ts` — client-side. `lib/db.ts` — Drizzle client. `lib/permissions.ts` — RBAC (owner/member/viewer).
- `src/lib/payroll-formula.ts` — Safe formula evaluator (no `eval()`); used for salary concept calculations.
- `src/lib/payroll-period-rules.ts` — Business rules: only previous month is liquidatable; only past months allow novedades/recibos.
- `src/lib/payroll-cron.ts` — Monthly salary scale auto-update using Gemini AI to parse CCT HTML.
- `src/scripts/` — One-off bulk migration scripts. Run individually with `bun run <script-name>`.
- `src/routeTree.gen.ts` — **Auto-generated by TanStack Router. Never edit manually.**

### Auth and multi-tenancy

Every server function must start with:

```typescript
import { getSessionWithOrg } from "./helpers";
const { session, orgId } = await getSessionWithOrg();
```

`getSessionWithOrg()` (in `src/actions/helpers.ts`) reads `session.activeOrganizationId` and throws if missing. All DB queries must scope to `orgId`. Roles: `owner > member > viewer` — checked via `lib/permissions.ts`.

If a session exists but has no active org, the user is redirected to `/no-organization`.

### Server Functions pattern

```typescript
// src/actions/feature.tsx
export const getThings = createServerFn({ method: "GET" })
  .handler(async () => {
    const { orgId } = await getSessionWithOrg();
    return await db.select().from(thingTable).where(eq(thingTable.orgId, orgId));
  });

export const createThing = createServerFn({ method: "POST" })
  .inputValidator(z.object({ name: z.string() }))
  .handler(async ({ data }) => {
    const { orgId } = await getSessionWithOrg();
    // ...
  });
```

### Adding a new route/feature

1. Create `src/routes/_authed/feature/index.tsx` with `export const Route = createFileRoute("/_authed/feature/")({ component: ... })`
2. Create `src/actions/feature.tsx` (always `getSessionWithOrg()` first)
3. Use `useQuery`/`useMutation` in components to call server functions
4. Invalidate query keys after mutations: `queryClient.invalidateQueries({ queryKey: ["feature"] })`

### Database schema — main tables

**Accounting:**
- `client` — Agrupador de entidades fiscales (representante o titular CUIT genérico, ligado a `orgId`). Contenedor en el que viven 1+ profiles. **No es la persona jurídica con CUIT propio** — eso es el `profile`.
- `profile` — Entidad fiscal individual (empresa con CUIT propio: `identity_number`, `identity_type`, dirección, email, etc.). Es donde viven los datos fiscales reales (deudas, notificaciones, IVA, sueldos por empresa). Configuraciones fiscales por entidad (cierre de ejercicio, situación frente al IVA, etc.) deben ir a este nivel.
- `credential` — External provider credentials (AFIP, etc.) per client.
- `invoice` — Inbound/outbound invoices with IVA breakdown and AFIP integration fields.
- `ivaScrape` — Monthly IVA scrape results; unique on `(profileId, periodoFiscal)`.
- `notification` — AFIP notifications with attachments.
- `job` / `jobLog` — Background job tracking (scraper jobs dispatched to ARCA Scrapper).
- `movements` — General ledger entries (income/expense).
- `fiscalEntity` — CUIL/CUIT catalog seen in invoices.
- `debt`, `dueDate` — Tax debt and due date tracking.

**Payroll (sueldos):**
- `payrollConvenio` — CCT (collective bargaining agreements) per client.
- `payrollConvenioCategoria` — Job categories within each CCT.
- `payrollEscala` — Salary scales by category with `vigenciaDesde`/`vigenciaHasta`.
- `payrollConcepto` — Configurable salary components with type, formula, base, and SOS code.
- `conceptosCompletosSos` — Global SOS concept catalog (codes 1–620).
- `liquidacionImportEmpleado` — Employee master records (`origen`: import vs manual).
- `liquidacionImportRecibo` — Pay stubs per employee per period.
- `liquidacionImportConceptoValor` — Line items in pay stubs (concept + value + origen).
- `obraSocial` — Health insurance catalog.

**Key enums** (in `drizzle/schema.ts`):
- `job_type`: `iva | comprobantes | comprobantes_full | notificaciones | deuda | vencimientos`
- `job_status`: `pending | running | failed | finished`
- `payroll_concepto_tipo`: `remunerativo | no_remunerativo | descuento | retencion`
- `payroll_concepto_base`: `basico | bruto | total_remunerativo | neto | custom | ...`

**LSD catalog tables** (códigos AFIP, no enums):
- `payroll_situacion` — Situaciones de revista (códigos 2 dígitos AFIP: "01"–"51"). Un recibo puede tener hasta 3 por período via `situacionRevista1Id/2Id/3Id` + `DiaInicio` en `liquidacionImportRecibo`.
- `payroll_condicion` — Condición del trabajador (códigos "00"–"14").
- `payroll_modalidad_contratacion` — Modalidad de contratación (códigos "001"–"998").
- `payroll_siniestrado` — Tipo de siniestro ART (códigos "00"–"13").
- `payroll_actividad` — Actividad económica (códigos "000"–"921").
- `payroll_zona` — Zona geográfica.
- `payroll_provincia` — Provincia.

### Payroll / Sueldos module

The payroll system handles Argentine payroll (liquidación de sueldos) with legal compliance:

- **Formulas** (`src/lib/payroll-formula.ts`): Safe expression evaluator (no `eval`). Supports variables: `basico`, `antiguedad`, `bruto`, `totalRemunerativo`, `neto`, plus arithmetic operators. Example: `"0.11 * basico"` = 11% of basic salary.
- **SOS concepts**: Standardized AFIP codes 1–620 representing salary line items. The `conceptoSos` tables map client-specific concepts to SOS codes.
- **LSD format**: Fixed-width file format for AFIP's Simplificación Registral (payroll reporting). Import/export logic lives in `src/actions/` payroll handlers.
- **Period rules**: Only the previous calendar month can be liquidated. Past months allow corrections (novedades) and receipt generation (recibos).
- **Scale auto-update**: `payroll-cron.ts` runs on day 20 of each month, scrapes CCT sources, uses Gemini to extract scales, and upserts into `payrollEscala`.

### External integrations

- **ARCA Scrapper**: Async jobs dispatched via `POST ${SCRAPPER_JOBS_URL}/api/jobs`. Env var fallback: `BACKEND_API_URL` → `http://localhost:3002`. The UI polls job status via `getJobs()` (no websockets). Job types: `iva`, `comprobantes`, `comprobantes_full`, `notificaciones`, `deuda`, `vencimientos`.
- **Google Gemini** (`GEMINI_API_KEY`): PDF text extraction (`src/actions/scannerAi.tsx`) and salary scale parsing from CCT HTML (`src/lib/payroll-cron.ts`).

## Conventions

- **Path aliases**: `@/` → `src/`, also resolves `@/lib/` and `@/drizzle/`.
- **Styling**: Tailwind utility classes only. No inline styles. Tokens in `tailwind.config.mjs`.
- **Icons**: Lucide React only.
- **Toasts**: Sonner — `import { toast } from "sonner"`.
- **Forms**: React Hook Form + Zod via `@hookform/resolvers/zod`.
- **DB access**: Only inside `src/actions/` server functions. Always filter by `orgId` (multi-tenancy).
- **ESLint**: TypeScript strict mode. Run `bun run lint:fix` before committing.

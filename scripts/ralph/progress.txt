## Codebase Patterns
(Will be populated by Ralph as it discovers reusable patterns. Read this section first before starting any user story.)

- Reusing dashboard KPI components in inline AI render: prefer extending the existing component with an optional pre-fetched data prop (like US-005's `items` and US-006's `stats`) over creating a new wrapper. When the prop is provided, gate the matching `useQuery` with `enabled: !skipQuery`. Other independent queries the component runs (e.g., `getOverdueDebts`, `getPendingNotificationsCount`) keep running and benefit from React Query cache reuse if the dashboard is already cached.
- The existing AI agent at src/routes/api/agent.ts uses Vercel AI SDK v6 (`ToolLoopAgent`, `gemini-2.5-flash`) and is read-only (SQL SELECT only). It MUST NOT be modified.
- The /chat page at src/routes/_authed/chat/{$id,index}.tsx uses @ai-sdk/react useChat with /api/agent endpoint. It MUST keep working unchanged.
- CopilotKit runs in PARALLEL to the existing agent — separate runtime endpoint at /api/copilotkit, separate floating UI (CopilotPopup), shared Gemini API key.
- Module gating: every feature in this PRD must respect the `ai_agent` module flag (listOrgModules from src/actions/admin.tsx, useQuery key ['orgModules']).
- Multi-tenancy: every server function calls getSessionWithOrg() first, scopes by orgId.
- Never expose client.password (AFIP credential) in any context (readable, action result, log).
- TanStack Start route handler signature: `{ server: { handlers: { POST: async ({ request }) => Response } } }` — see src/routes/api/agent.ts for the canonical pattern.
- Module gate pattern (from US-055 of the previous Ralph run): `beforeLoad` with `throw redirect({ to: '/' })` requires `// eslint-disable-next-line @typescript-eslint/only-throw-error` before each throw.
- CopilotKit runtime endpoint (US-001): use `copilotRuntimeNextJSAppRouterEndpoint` from `@copilotkit/runtime` — its `handleRequest(req: Request)` works with TanStack Start's Web Request/Response model. No Node adapter needed. Pair with `GoogleGenerativeAIAdapter` and `process.env.GEMINI_API_KEY`.
- New routes under `src/routes/` only get into `src/routeTree.gen.ts` after the dev server (vite + tanstackStart plugin) runs once; until then `tsc` will complain. Run `bun run dev` briefly to regenerate.
- TS auth session shape: cast `(session.session as { activeOrganizationId?: string | null }).activeOrganizationId` — Better Auth doesn't type the org plugin field on the base type.
- Module gating (US-002): `listOrgModules` server fn in `src/actions/admin.tsx` reads `organization.metadata` (JSON string) → `{ ai_agent: boolean }`. Defaults to `{ ai_agent: true }` when metadata is null/invalid. Consume via `useQuery({ queryKey: ['orgModules'], queryFn: () => listOrgModules() })`. The hook returns `undefined` while loading — treat that as "disabled" and upgrade once data resolves so the provider is never blocking.
- `getSessionWithOrg()` returns `orgId` typed as `any` (helpers.ts uses `as any`). When passing to drizzle `eq()` in a NEW server function, cast at the call site: `const { orgId } = (await getSessionWithOrg()) as { orgId: string }` to avoid a fresh `no-unsafe-argument` lint error. Existing actions tolerate the error; new code shouldn't add to the count.
- CopilotKit provider must be conditional but NEVER block render of the shell. Render the shell first, wrap in `<CopilotKit runtimeUrl="/api/copilotkit" agent="default">` only when `aiAgentEnabled` is true. Import `@copilotkit/react-ui/styles.css` once at the top of the route file — CSS class names are scoped enough that they don't visually leak when no CopilotKit DOM is present.
- CopilotPopup (US-003): import `{ CopilotPopup }` from `@copilotkit/react-ui` and place it as a sibling of the shell *inside* the `<CopilotKit>` provider. It is a fixed-position floating button (bottom-right) so it does not shift layout. Hide it on `/chat` and `/chat/$id` to avoid double UI alongside the existing dedicated chat. Use `useRouterState({ select: (s) => s.location.pathname })` (already in scope) — `useLocation()` would also work but the existing route file uses `useRouterState`. Provide labels via `labels={{ title, initial, placeholder }}` — the `CopilotChatLabels` interface lives at node_modules/@copilotkit/react-ui/src/components/chat/ChatContext.tsx if you need to extend later.
- CopilotActions hook component (US-004+): client-only component that calls `useCopilotAction(...)` for each action and returns `null`. Mount it INSIDE `<CopilotKit>` provider but OUTSIDE the shell so the registrations live for the lifetime of the provider. New actions go in `src/components/copilot/CopilotActions.tsx`. Server fns that back actions live in `src/actions/copilot.tsx`.
- Generative UI render (US-004): `useCopilotAction` `render` prop receives `{ status, args, result }`. `status` is `'inProgress' | 'executing' | 'complete'`. Show a spinner while non-complete (Gemini may render the tool call before the handler returns). When `result` is undefined return a fallback. Cast `result` to your typed result via `result as MyResultType` since CopilotKit types it as `any`.
- Action `parameters` array uses `{ name, type: 'string' | 'number' | 'boolean', description, required }`. Optional params still arrive in handler args but may be `undefined` — coerce with `?? undefined` before passing to a Zod-validated server fn that uses `.optional()`.
- Reusing big stateful components in inline AI render (US-004): `RenderIvaResume` is heavy (own queries, editable rows, Excel export). Wrapping it works because it accepts `clientId`, `selectedProfileId`, `dateRange`, and a `clientIva` blob — all of which can be derived from the action's resolved client+profile+period. The wrapper (`CopilotIvaResume`) builds `clientIva` from the action result's `ivaScrape` row and lets RenderIvaResume re-query invoices itself. Don't try to feed pre-computed totals into RenderIvaResume — it computes from invoices via React Query. The action's role is *resolution* (name → uuid) and providing the AFIP scrape data, not pre-computation for display.
- React Hooks rules in conditional render: when a component branches on `'error' in result`, ALL hooks (`useState`, `useEffect`, etc.) MUST be called before the conditional return. Use `const isError = 'error' in result;` to extract the discriminator, then call hooks based on safe values (e.g. `const perfiles = isError ? [] : result.perfiles`), THEN do `if (isError) return <ErrorView />`.
- `dbReadonly.execute(sql.raw(...))` returns an iterable whose item type isn't `Record<string, unknown>` — drizzle types it loosely. ESLint flags `as Record<string, unknown>[]` as "unnecessary assertion". Workaround: type via `Iterable<{ field: type }>` cast on the source, then `Array.from(rows as Iterable<...>)` returns the right type without a no-unnecessary-type-assertion warning.
- useCopilotReadable safety (US-007): the hook calls `useCopilotKit()` internally, which subscribes to the runtime via `useEffect`. When the CopilotKit provider is NOT mounted, the default context value has `copilotkit: null`, so the subscribe call inside `useCopilotKit`'s effect would crash. Workaround: never call `useCopilotReadable` directly in pages that render outside the provider. Instead, gate via `useQuery({ queryKey: ['orgModules'] })` and only render a tiny `<CopilotReadableEntity description value />` wrapper component when `aiAgentEnabled` is true. The wrapper is at `src/components/copilot/CopilotReadableEntity.tsx` and is reusable for any "expose entity context to Copilot" need.

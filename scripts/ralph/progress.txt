- **Learnings for future iterations:**
  - The Next.js App Router endpoint from @copilotkit/runtime is the correct adapter for TanStack Start since both speak Web Request/Response. Don't waste time on `copilotRuntimeNodeHttpEndpoint` (req/res Node style).
  - CopilotRuntime is heavy to instantiate; defined at module scope so it's reused across requests (the auth/session check still runs per request inside the handler).
  - The route file was emitted at /api/copilotkit BEFORE running dev once — `tsc` complains because `keyof FileRoutesByPath` doesn't include the new path until vite regenerates `src/routeTree.gen.ts`. After one dev start, the route tree updates and tsc/lint pass.
  - System instructions: there's no clean server-side hook to prepend a system prompt with this version of the runtime (middleware on CopilotRuntime is deprecated). Best place is the client-side `<CopilotKit instructions={...}>` prop in US-002. For now SYSTEM_INSTRUCTIONS is exported via runtime properties so US-002 can read it from there if desired.
  - Always cast Better Auth session: `(session.session as { activeOrganizationId?: string | null }).activeOrganizationId` — same pattern src/routes/api/agent.ts uses with `as any`. We used the typed cast for cleaner lint.
